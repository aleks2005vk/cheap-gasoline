# 🚀 Firebase Custom Claims - Система ролей

## Обзор

Приложение теперь использует **Firebase Custom Claims** для управления ролями пользователей. Это обеспечивает более безопасную и масштабируемую систему авторизации.

## Роли пользователей

| Роль            | Описание             | Разрешения                           |
| --------------- | -------------------- | ------------------------------------ |
| `admin`         | Полный доступ        | Все права, управление пользователями |
| `moderator`     | Модератор            | Одобрение цен, модерация             |
| `station_owner` | Владелец станции     | Управление своей станцией            |
| `user`          | Обычный пользователь | Просмотр, предложение цен            |
| `guest`         | Гость                | Только просмотр                      |

## 🔧 Настройка ролей

### 1. Найти Firebase UID пользователя

1. Зайдите в [Firebase Console](https://console.firebase.google.com)
2. **Authentication** → **Users**
3. Нажмите на пользователя
4. Скопируйте **UID** (например: `abc123def456`)

### 2. Назначить роль через скрипт

```bash
cd backend
python set_role.py set <FIREBASE_UID> <ROLE>
```

**Примеры:**

```bash
# Назначить админа
python set_role.py set abc123def456 admin

# Назначить модератора
python set_role.py set def789ghi012 moderator

# Проверить роль
python set_role.py get abc123def456

# Показать всех пользователей
python set_role.py list
```

### 3. Управление через Admin Panel

1. Войдите как админ
2. Перейдите в **Admin Panel** (`/admin`)
3. Выберите пользователя
4. Измените роль в выпадающем меню

## 🔒 Безопасность

- **Custom Claims** хранятся в Firebase токенах
- Роли проверяются при каждом API запросе
- Изменения ролей вступают в силу при следующем входе пользователя
- Только админы могут менять роли

## 📡 API Эндпоинты

### Получить всех пользователей с ролями

```http
GET /api/admin/users-with-roles
Authorization: Bearer <token>
```

### Изменить роль пользователя

```http
POST /api/admin/set-user-role?firebase_uid=<uid>&role=<role>
Authorization: Bearer <token>
```

### Получить роль конкретного пользователя

```http
GET /api/admin/user-role/{firebase_uid}
Authorization: Bearer <token>
```

### Создать нового админа

```http
POST /api/admin/create-admin
Content-Type: application/json
Authorization: Bearer <token>

{
  "email": "user@example.com"
}
```

## 🔄 Миграция с локальных ролей

Если у вас есть пользователи со старыми ролями в базе данных:

1. **Экспортируйте** текущих пользователей из БД
2. **Назначьте роли** через Firebase Custom Claims
3. **Обновите** код для чтения ролей из токенов

## 🐛 Устранение неполадок

### Пользователь не видит новую роль

- Пользователь должен **выйти и войти снова**
- Токен обновляется при следующем входе

### Ошибка "Admin access required"

- Проверьте роль через `python set_role.py get <uid>`
- Убедитесь, что токен не истек

### Firebase ошибка

- Проверьте файл `firebase-service-account.json`
- Убедитесь, что сервисный аккаунт имеет права на Auth

## 📝 Логирование

Все изменения ролей логируются в Firebase Console:

- **Authentication** → **Users** → **User events**
